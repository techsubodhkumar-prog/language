1. System Architecture
The architecture separates the Flutter client from server-side business rules. The backend is authoritative for authorization, eligibility, activity lifecycle, join approvals, and participant
capacity.
Activity Discovery Platform — System Architecture & Database Diagrams Page 2

Recommended MVP stack: Flutter/Dart mobile client; versioned HTTPS API; PostgreSQL relational database; a realtime service for activity chat; push notifications; object storage for
images; and a protected moderation/admin console. A cache or job queue can be added when load or retry needs justify it.

3. Activity Creation and Matching Workflow
Important: users who share an interest should not automatically receive unlimited unsolicited messages. The system should make activities discoverable and send notifications only under
user preferences, visibility rules, eligibility checks, and rate limits.

5. Critical Integrity and Security Rules
(cid:127) Use a unique constraint on (activity_id, user_id) so a user cannot occupy duplicate membership records.
(cid:127) Use a database transaction or atomic conditional update to enforce max_participants under concurrent join requests.
(cid:127) Store timestamps consistently (prefer UTC); display local time to each user.
(cid:127) Enforce private activity, chat, and membership authorization on the backend for every request.
(cid:127) Keep exact live location private by default; use a selected public venue or approximate area for discovery.
(cid:127) Treat report targets carefully: validate target_type and target_id, and restrict report evidence to authorized moderators.

(cid:127) Use pagination and indexes for activity discovery, especially category, status, start_at, and geographic filtering.
(cid:127) Use soft-delete/anonymization and retention policies thoughtfully; document exceptions for abuse/security records.
(cid:127) Use rate limits for registration, activity creation, invitations, join requests, and messages.
(cid:127) Do not put passwords, access tokens, or private message content in application logs.
6. Suggested Indexes
Illustrative indexes: activities(status, start_at); activities(category_id, status, start_at); activity_memberships(activity_id, status); activity_memberships(user_id, status);
messages(activity_id, created_at); notifications(user_id, read_at, created_at); reports(status, created_at); user_interests(interest_id, user_id). Add a spatial index if PostgreSQL/PostGIS is
used for location queries.
